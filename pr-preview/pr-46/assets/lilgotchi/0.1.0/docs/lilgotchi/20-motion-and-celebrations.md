# Scenery, movement and growth moments

The pet canvas stays a complete 32 by 16 pixel play area. Landscape decoration lives in a separate 24 pixel strip above it inside the bezel. It never overlays bodies, waste, sickness indicators or game effects. The original family uses rolling hills, Slice uses triangular hills, and Cyberpunk uses a small skyline. All families share local morning, afternoon, evening and night periods. Night uses a quiet moon and two static stars. Lights off and sleep darken the strip and hide the celestial marker. E ink uses a static grayscale landscape.

There are no additional text labels in the scenery. Time remains above the display. Stage, needs and growth updates remain below the egg. Decorative landscape markup is aria hidden and ignores pointer events. No scenery animation or flashing is used.

Body movement stays on whole logical pixels and goes through the existing collision aware placement function. Idle sway travels one pixel each way. Eating, play and happiness bounce one pixel. Sleep breathes by one pixel. The land mode is a single two pixel drop that settles after 650 milliseconds, used immediately after a growth transition. It does not loop or indicate death. E ink and reduced motion return zero offsets. Calm idle pets also use a gentle pixel tilt: the upper rows shift one pixel while the lower rows stay anchored. Two transparent padding columns preserve every original pixel and palette value. Frames already wider than 14 pixels keep their original pose so the body never exceeds its 16 pixel allocation. Busy care scenes skip tilt. This is the pixel art counterpart of rotation, not a blurred whole canvas transform. Distinct drawn reaction frames provide larger pose changes.

A growth update appears in the flat care area beneath the identity. It names the new character and stage, and distinguishes hatching from later growth. It remains visible until Got it is pressed or a newer growth event replaces it. It never steals keyboard focus. The message uses a polite status announcement, and its button has a full touch target. Only the new card enters with a short fade and three pixel rise, disabled for reduced motion and E ink. No confetti or flashing occupies the LCD.

The card is a presentation event for the open session, not a permanent journal. It survives normal UI refreshes. Reload history and changes while away are handled by the separate return summary and pet history features. Existing saved adults do not receive a fake hatch event merely because they were opened. Resets clear a pending growth card. Multiple offline transitions should produce one final card or the existing return summary, not a queue of announcements.

## Integration

Load pets/scenery.css after embed.css. Before the canvas inside screen-frame, add a scene-window with scene-orb and scene-land spans, all aria hidden. Add growth-notice with hidden below pet-identity. Construct GrowthCelebration with that element. Capture previous character, stage and birth metadata before applying a growth transition, then call observe(previous, currentState) after it. Do the same for the secret adult. Suppress intermediate offline cards and show the final transition once catch up ends. Clear on reset and restart.

For a landing reaction, call motionOffset with elapsed milliseconds since growth and kind land during the first 650 milliseconds after the existing evolution effect. Keep the existing safe placement function and pass reducedMotion and eink options if invoking the helper directly. Existing game petMotion guards already disable optional motion.

Validation covers source color and pixel count conservation for tilt, composed bounds in all families, all local period boundaries, dark and sleep precedence, integer bounded offsets, the nonlooping landing endpoint, reduced motion, no fake events on reopen, duplicate dismissal, and card text safety. Browser review must check all three families, narrow width and open overlays.
